# NVMe PLE reader review, 2026-10-27

The reader in `ssd_stream/` was last reviewed against `madlabs/main@84f09ea980`,
a commit on madlabs/main-next (upstream f6fcda8827) that is not in madlabs/main's
history. madlabs/main is now `ae7ec4de75`, on upstream fe89a7c890. Seven of the
11 modules the source guard pins differ between the two, so NVMe mode exited
at startup on madlabs/main. This review covers each of the seven, and the
SGLang code the reader uses outside the guard.

Line numbers are at `ae7ec4de75` for SGLang files (under `python/sglang/srt/`)
and at this commit for reader files (under `ssd_stream/src/sglang_ssd_stream/`).

## models.qwen4_exp

Commits since `84f09ea980`: 8ff02f5820 (#41729), 142800d641 (#44150),
8a18f5888f (#43032), d2874d97af and fe0d496131 (the packed PLE prefill and its
hardening), f07c1a398e (#42478), b157d548bb (#42301), 1f299e9f2f (#42481),
dc0b394471 (#42936), 234ccba7f6 (#43460), 0eb24e7d5b (#42175), 0d130f1915
(#39724), 2a8e9db3b0 (#39798), and 6dae25d1d1 and 95300400b0, the rebased
ports of the MXFP8 and loader commits that `84f09ea980` already had.

Unchanged for the reader:

- `Qwen4ExpNGramEmbedding` (`models/qwen4_exp.py:646-952`) is identical at both
  commits, including the meta-device build when `ple_offload_embedding` is on
  (`:717-742`) and every method the subclass calls.
- `Qwen4ExpPLELayer.__init__` keeps its signature and the attributes the
  subclass reads (`:1132-1205`). The layer is still built with `config`
  positional and `ple_layer_index` as a keyword (`:1698-1704`), which
  `Qwen4PLELayer.__init__(*args, ple_layer_index=0, **kwargs)` accepts.
- `start_prefetch(batch, forward_batch)` and
  `_consume_prefetched_embeddings(forward_batch)` keep their signatures. The
  model now passes keywords, `batch=` and `forward_batch=`
  (`:2295-2302`), which match the subclass's parameter names. `forward_idle`
  (`:1380-1384`) still empties a pending prefetch through the overridden
  method, so only the subclass reads its own `_prefetch_state` tuple.
- `_prepare_ple_batch(input_ids, forward_batch, *, ngram_size,
  ngram_eos_token_id)` (`:248`) keeps its signature. `_PLEBatch` gains
  `query_start_loc` (`:189`), set only for EXTEND, MIXED and SPLIT_PREFILL.
  The reader calls it only in decode and verify graph replay.
- `load_weights` (`:2531`) is unchanged.
- The MXFP8 conversion still skips the PLE subtree by the module-level name
  `Qwen4ExpPLELayer` (`:1814`), which the REPLACE hook points at the subclass.

Changed:

1. **Breakable prefill CUDA graphs.** 8ff02f5820 put
   `Qwen4ExpForConditionalGeneration` on the multimodal breakable allowlist
   (`configs/model_config.py:2402`). On `84f09ea980` it was left off on
   purpose ("QSA builds host-side sparse metadata per forward"), so its
   prefill ran eager. The prefill default is breakable on CUDA
   (`model_executor/cuda_graph_config.py:119-123`). The same commit added a
   breakable PLE path: the prepare, prefetch, forward and commit steps run as
   eager breaks (`models/qwen4_exp.py:194-245`), and the prefetch is
   `_breakable_ple_prefetch` (`:212-217`, called at `:2298`). A breakable
   replay keeps capture mode on
   (`model_executor/runner_utils/capture_mode.py:44-45`), and upstream's own
   `_get_prefetch_buffer` now checks for that (`models/qwen4_exp.py:1397-1399`).

   The subclass keys both of its decisions on `get_is_capture_mode()` alone:
   which buffer to use (`qwen4.py:70`) and whether to read rows or only wait
   on the graph event (`qwen4.py:108-116`). In a replayed prefill it would
   bind a captured buffer for the live token count and read nothing, so each
   PLE layer would add zero or stale rows. It would also keep one buffer per
   distinct prefill length. Nothing on that path raises, so the server would
   start and serve those rows.

   Action (`edcaf4109c`): in NVMe mode `configure_cli` sets
   `--cuda-graph-backend-prefill disabled` when the launch picks no prefill
   graph, and refuses to start when it asks for one (`config.py:161-199`). It
   reads `--cuda-graph-config`, `--cuda-graph-backend-prefill` and the two
   disable flags in SGLang's precedence (`arg_groups/cuda_graph_hook.py:54-95`).
   An explicit choice is locked, so the step that re-enables breakable
   prefill for prefill CP leaves it alone (`arg_groups/cuda_graph_hook.py:103-122`).
   This matches what the reader was reviewed for: it stages rows only for
   decode and verify graph replay (`README.md`, "Source and limits"). Serving
   breakable prefill from NVMe would change the reader's data path and is not
   attempted here.

2. **Packed PLE prefill** (8a18f5888f, d2874d97af, fe0d496131). `_short_conv`
   takes a packed path when `query_start_loc` is set (`:1222-1256`), the
   valid-token mask is skipped for packed batches (`:1561`), and intermediates
   are freed early (`:1481` onward). All of this runs on the embeddings the
   subclass returns from `_consume_prefetched_embeddings`, in the same shape
   (processed tokens by `ple_embed_dim`). The subclass overrides neither
   `forward` nor `_short_conv`. No change.

3. **`_get_prefetch_buffer`** (`:1394-1410`) now skips graph buffers inside a
   breakable graph. The subclass's override (`qwen4.py:67-77`) keeps the old
   test. With prefill graphs off (item 1) no breakable graph reaches it, so it
   is left as it is.

4. **Layers built from stage boundaries** (f07c1a398e and the refactors after
   it). The PLE contribution moved from `_prepare_qwen4_exp_attn` into the
   attention stage's read, `_add_ple_embedding` (`:1886-1905`), which still
   calls `self.ple(residual, forward_batch, ple_batch)`. The prefetch for layer
   i+1 still starts before layer i runs (`:2292-2302`). No change.

5. **Prefill context parallel** (0d130f1915). `_add_ple_embedding` gathers rows
   across CP ranks (`:1899-1904`). CP needs more than one GPU; the reader is
   qualified for TP1 only. Not reviewed further.

  2.14.1, SGLang's CPU-installable dependencies, the reader built by

  `test_config.py`, `test_graph_hooks.py`, `test_offload.py` and

  `disabled`, the disable flags pass, and every request for a breakable or full
  prefill graph is refused.
